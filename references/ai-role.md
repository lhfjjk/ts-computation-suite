# AI 在过渡态寻找与计算中的实际作用

> 这份文档回答一个问题：**现在（2026-10）AI 到底帮上了什么忙，哪些忙还帮不上。**
> 结论先行：AI 目前最有价值的角色是“候选生成器 + 预筛器 + 流程编排器”，不是
> “替你做电子结构判断的人”。它能把搜索空间缩小、把重复劳动自动化，但不能替代
> 自旋态、连通性、虚频模式和 IRC 的验证。

---

## 1. 先区分四种“AI”，否则会过度承诺

| 层级 | 代表 | 实际做什么 | 不能做什么 |
|---|---|---|---|
| **生成模型** | UniTS-Gen 等 | 从 2D 图 + 反应位点生成 3D TS 初猜 | 不保证初猜是目标通道；不保证大体系/BS 面可用 |
| **自动搜索算法** | ORCA GOAT-TS | 自动探索构象/反应通道，找鞍点候选 | 不便宜；100+ 原子很慢；仍需 DFT 精修与验证 |
| **ML 势 / 代理模型** | MACE/NequIP/ANI、Δ-ML | 加速 MD、几何优化、构象枚举、垒的近似 | 不能给出 1 kcal 级过渡金属垒；不能替代高精度单点 |
| **LLM / Agent** | 本类工具 | 生成输入、解析输出、监控作业、检索文献、编排流程 | 不能判断机理、验证电子态、替代人工决策 |

一句“AI 找到了 TS”可能只是“生成器给了初猜，DFT 收敛了”。报告时必须拆开。

## 2. 项目里的实测证据

这些数字来自 `S_H2-orca` 与 `双自由基手性` 两个课题，不是文献转述。

| 任务 | 方法 | 结果 | 结论 |
|---|---|---|---|
| UniTS-Gen 单次生成 | 论文自报 | 68.7% 收敛到一阶鞍点；人工筛除无效 TS 后 **41.9%** 正确（均过 IRC） | 单次不能定论 |
| UniTS-Gen 多采样 | 论文自报 | 5 个此前失败的 Formula-OOS 案例，每个 10 个样本，**5/5** 得到正确 TS | 多采样是正确用法 |
| 84 原子 Ni–BS 有机金属 | UniTS-Gen | 4 个 PASS，但重原子 RMSD **3.61–4.36 Å**；没有一个同时具备 Ni–C 仍成键 + C···C 接近 | **分布外，不可用** |
| 找 TS 剖面 | ORCA `%geom Scan` | 任意一点撞 `MaxIter` → 整条扫描报废，实测 **3 次** | 不要用 Scan 做长剖面 |
| 找 TS 剖面 | 逐点独立 `! Opt`（非 AI 自动化） | **16/16** 全部收敛；两次弄死扫描的 R 点 1 只用 44 周期 | **最大时间节省来自流程，不是模型** |
| 模式位移 | 按最大原子位移 0.18 Å | Cβ–H 实际变化 **−0.31 Å**，183 周期单调下降扎进反应物盆地 | 位移要按目标键长定标 |
| 模式位移 | 按目标键长变化 0.05 Å | 落在真 TS 邻域 | 物理规则，不是 AI |
| R/S 中间体差 | 单构象 DFT | 配体叠合 RMSD **1.62 Å**；差值构象主导 | 不做构象搜索就不能报立体选择性 |
| 六元环 TS 补算 | 两轮沿软模位移 + OptTS | 两轮都滑回同一二阶鞍点，能量差 **0.003 kcal**；DefGrid3 证明软模为真 | 第三轮没有意义，止损比“再试一次”值钱 |

**最重要的观察**：在这个项目里，真正节省时间的不是生成模型，而是
“逐点独立 Opt 替代 Scan”“Hessian 复用”“0.05 Å 位移定标”“两轮重复就停”。
这些是**流程和物理规则**，不是 AI。AI 的增量在候选生成和预筛，不在验证。

## 3. AI 现在能帮什么

### 3.1 候选生成（最成熟）

适合：

- 小到中等体系（约 < 60–80 原子）、有机或主族、闭壳层/普通开壳层；
- 反应类型在训练分布内；
- 需要“多试几个初始猜测”，而不是“一次命中”。

正确用法是**多采样 + 预筛**，不是单次生成直接跑 OptTS：

```bash
# 用你选择的生成器（UniTS-Gen / GOAT-TS / 手搭）产出多帧 candidates.xyz
# 然后做物理预筛：clash / RMSD / 连通性
python scripts/ts_prefilter.py --cand candidates.xyz \
    --reactive 56,57 --forming 56,57 --write-pass pass.xyz
```

预筛后再走 L1/L2。**生成 10 个、只对 1–3 个跑 DFT**，这是成本最低的形态。

### 3.2 构象枚举

柔性配体/长链的 R/S 或底物比较，第一步不是找 TS，而是找构象。AI/ML 势
（或 xtb）可以快速生成 10–50 个构象，聚类后保留 3–5 个低能构象。它不能替你
判断“哪个构象决定了选择性”，但能把“单构象大数”这种错误提前暴露。

### 3.3 垒的代理预测

ML 势/Δ-ML 可以在**数量级**上估计垒，用于：

- 排序候选通道，决定先算哪一个；
- 在扫描前粗定位垒区；
- 识别明显不可能/明显放热的步骤。

不要用它报 1 kcal 级的选择性。过渡金属的配位键、自旋态、溶剂化仍是短板。

### 3.4 输入生成、输出解析、监控

这是 LLM/Agent 最稳的贡献：

- 从模板生成 ORCA/Gaussian/Slurm 输入，减少格式错误；
- 解析 `.out`/`.log` 的能量、虚频、⟨S²⟩、收敛标志；
- 监控队列，避免并行 ORCA、等待者竞态、作业孤儿；
- 把失败诊断路由到下一步（例如 P2 最低模不牵动反应对 → 不进 P3）。

这些工作不“聪明”，但很容易出错；自动化收益是直接的。

### 3.5 文献与机理假设

检索 + LLM 可以快速整理“同类反应的 TS 几何/配体/自旋态”，提出候选机理。
它提出的是**假设**，不是证据；必须用计算或实验验证。

### 3.6 主动学习

让模型选择“下一个算哪个底物/配体/构象”，把 DFT 预算花在信息量最大的点上。
这是最有前景的方向，但前提是有一个一致的数据集和可靠的预筛。

## 4. AI 现在不能帮什么

| 任务 | 为什么不能 |
|---|---|
| **定义基元步骤/机理** | 需要化学判断和实验约束；模型只能给候选，不能决定“哪条通道是真的” |
| **枚举自旋态、设置 BS** | dⁿ 状态、BS 解、`FlipSpin`、单点继承，都是电子结构问题；模型经常漏 |
| **验证连通性/模式身份/IRC 端点** | 需要读几何、键长、模式投影；生成模型不保证物理自洽 |
| **1–3 kcal 窗口的 TM 选择性** | DFT 误差本身就有 2–5 kcal；ML 代理更差；没有校准不确定性就不能报 |
| **分布外催化剂/配体** | 训练数据稀疏；84 原子 Ni–BS 体系实测失败 |
| **失败反应数据** | 文献只报成功反应；可行性预测有幸存者偏差 |
| **“理解”化学** | 当前模型更擅长插值；因果结构需要物理约束和验证 |

## 5. 一个现实的 AI 辅助闭环

```text
人：定义反应对、电荷/多重度、自旋面、参考态
        │
        ▼
AI：生成 N 个候选（多采样） ──► 物理预筛（clash/RMSD/连通性/距离）
        │                                   │
        │                                   ├─ 大多数候选在这里死掉
        ▼                                   ▼
   只对前 1–3 个跑 L1（约束 Opt+Freq） ──► 最低模门禁
        │                                   │
        ▼                                   ▼
   L2（OptTS + 读 Hessian） ──► 虚频/定域度/键长/IRC/⟨S²⟩
        │                                   │
        └──────────► 反馈：哪些候选/构象/自旋值得下一批
```

关键点：

1. **AI 的输出是“排序的候选集 + 不确定性”，不是单个答案。**
2. **物理预筛必须在 DFT 之前**；否则只是把错误的候选算得更快。
3. **验证必须独立于生成模型**；生成模型不能给自己的候选打分当证据。
4. **人保留最终判断**：接受、换模型、换通道、披露限制。

## 6. 如何报告 AI 的作用

不要写“AI 找到了 TS”。写清楚四件事：

| 项目 | 例子 |
|---|---|
| 工具/版本 | UniTS-Gen commit/权重版本；GOAT 的 ORCA 版本 |
| 候选数/通过率 | 生成 10 个，预筛 4 个 PASS，DFT 3 个收敛，2 个一阶鞍点，2 个过 IRC |
| 验证级别 | 只做了 OptTS？还是 Freq + IRC + 自旋检查？ |
| 人工干预 | 手搭了几个？改了哪些约束/构象/自旋？ |

时间节省也要分项：候选生成、预筛、Hessian 复用、逐点扫描、止损。把
“流程自动化”与“模型能力”混在一起，会让结论不可复现。

---

## 7. 风险与边界

- **幻觉/错误候选**：生成模型可能给出化学上不合理的结构；必须预筛。
- **基准污染**：随机划分的 benchmark 会高估性能；用新底物/新催化剂/新反应类型做 OOD 划分。
- **过度承诺**：AI 是插值器，不是理解者；在 1–3 kcal 的选择性窗口里，误差可能比信号大。
- **责任**：最终判断、披露限制、报告不确定性，仍然是人。
- **数据**：过渡金属、失败反应、溶剂/反离子效应都稀疏；没有数据，模型只能猜。

---

## 8. 结论

AI 已经把“找 TS”从“凭直觉手搭一个猜测”变成“生成一批候选 + 物理筛选 +
DFT 验证”的流水线。它最成熟的贡献是：

1. **多采样候选生成**（小体系、分布内反应）；
2. **构象/通道枚举**；
3. **输入生成、输出解析、作业监控**；
4. **主动学习选择下一个计算点**。

但本项目最大的时间节省来自**流程规则**，不是模型：逐点独立 Opt 替代
ORCA Scan（16/16 vs 3 次整条报废）、Hessian 复用（避免 300 周期漂移）、
0.05 Å 位移定标（避免 183 周期错误）、两轮重复就停（省 10–20 h）。

所以正确的定位是：

> **AI 提议，物理过滤，DFT 验证，人决策。**

这也是本技能把 `ts_prefilter.py`、`ts_scan_pts.py`、`ts_verify.py` 和
`gauss_verify.py` 放在 AI 生成器之前/之后的原因：AI 负责缩小空间，
物理和电子结构负责说“不”。
